# Перенос проекта LIVS BI на другой компьютер (ноутбук)

Цель: поднять проект на ноутбуке 1-в-1, **не потеряв ни данные, ни дашборды, ни контекст Claude**.

> ⚠️ Главное, что нужно понимать: **не все данные лежат в файлах проекта.**
> - Данные БД (продажи, остатки, 1С) — в Docker-томе Postgres → уже выгружены в `backup/livs_bi.dump`.
> - Дашборды Metabase — во встроенной H2-базе → уже вынесены в `metabase-data/` и подключены томом (переезжают вместе с папкой).
> - Контекст Claude (память + история диалогов) — **вне папки проекта**, в `~/.claude/` → копировать отдельно (см. раздел 4).

Всё, что нужно для переезда, уже подготовлено на этом ПК. Осталось перенести и развернуть.

---

## 0. Что уже сделано на этом ПК (не повторять)
- `backup/livs_bi.dump` — полный дамп БД (147 МБ, проверен, 19 таблиц с данными).
- `metabase-data/metabase.db.mv.db` — H2-база Metabase со **всеми** дашбордами (id 2,3,4,5,6).
- `docker-compose.yml` — Metabase теперь монтирует `metabase-data/` (дашборды персистентны и портативны).
- `db/01_schema.sql`, `db/02_marts.sql` — схема актуальна (`group_name`, `cost_rub`, `v_stock_latest.product`).

## 1. Способ переноса — выбери один

### Способ A (рекомендуется) — всей папкой, одним архивом
Проект целиком ~**365 МБ**. Проще всего:
1. Заархивировать папку `D:\ToLivs\livs-bi` в zip.
2. Перекинуть на ноутбук (Google Drive / USB / внешний диск).
3. Распаковать на ноутбуке по **тому же пути** `D:\ToLivs\livs-bi` (см. примечание про путь в разделе 4).

### Способ B — git + облако (если хочешь синхронизировать изменения кода туда-обратно)
1. На этом ПК: `git init; git add .; git commit -m "LIVS BI"` → запушить в **приватный** репозиторий (GitHub/GitLab).
   `.gitignore` уже исключает тяжёлые `backup/`, `metabase-data/`, `incoming/`.
2. Эти три папки перекинуть отдельно (облако/USB) — без них база и дашборды будут пустыми.
3. На ноутбуке: `git clone …`, затем положить рядом `backup/`, `metabase-data/`, `incoming/`.

## 2. Подготовка ноутбука (один раз)
1. Установить **Docker Desktop** (Windows) — https://www.docker.com/products/docker-desktop
2. Запустить Docker Desktop, дождаться статуса *Running*.
3. Первый запуск делать **с интернетом** — Docker скачает образы `postgres:16` и `metabase`. Дальше можно работать офлайн (в дороге).

---

## 3. Развернуть проект на ноутбуке
Открыть PowerShell в папке проекта (`D:\ToLivs\livs-bi`) и выполнить по шагам:

```powershell
# 3.1 Поднять только БД (создаст схему из db/*.sql на чистом томе)
docker compose up -d --build db

# 3.2 Дождаться, пока БД станет healthy
docker inspect --format '{{.State.Health.Status}}' livs_db   # повторять, пока не "healthy"

# 3.3 Залить дамп данных поверх пустой схемы
docker cp backup/livs_bi.dump livs_db:/tmp/livs_bi.dump
docker compose exec -T db pg_restore -U livs -d livs_bi --clean --if-exists --no-owner /tmp/livs_bi.dump

# 3.4 Поднять остальное (Metabase подхватит дашборды из metabase-data/, app, ui)
docker compose up -d --build
```

Проверить: открыть в браузере
- **Metabase** → http://localhost:3000 (логин/пароль — см. `CREDENTIALS.local.md`, вне git)
- **GUI загрузки отчётов** → http://localhost:8501

> Если `pg_restore` ругается на пару строк про already exists / does not exist — это нормально при `--clean` на свежей схеме, данные зальются.

## 4. Сохранить контекст Claude Code (важно — «не потерять смысл проекта»)
Контекст Claude — в двух местах:

**A. Внутри папки проекта (переедет само):**
- `AI_ARCHITECTURE.md`, `AI_CURRENT_STATE.md`, `AI_ERROR_LOG.md` — рабочая память проекта.
- `Вопросы_к_встрече.md` — подготовка к встрече.

**B. Вне папки — скопировать вручную** с этого ПК на ноутбук:
- `C:\Users\Cipinkos\.claude\projects\d--ToLivs\` → в `C:\Users\<пользователь_ноута>\.claude\projects\d--ToLivs\`
  (там лежат авто-память `memory\` **и** полная история диалогов `*.jsonl` — с ней Claude помнит всё, что мы делали).
- (по желанию) `C:\Users\Cipinkos\.claude\CLAUDE.md` — глобальные инструкции (graphify).

> 🔑 **Про путь.** Имя папки `d--ToLivs` привязано к пути запуска `D:\ToLivs`. Чтобы память и история
> подхватились автоматически, запускай Claude Code на ноутбуке из **того же пути `D:\ToLivs`**.
> Если диска D: нет — распакуй, например, в `C:\ToLivs`, тогда переименуй скопированную папку
> `d--ToLivs` → `c--ToLivs` (формат: буква диска + `--` + путь через `-`). Либо запусти Claude Code
> один раз в новом месте, посмотри, какую папку он создаст в `~/.claude/projects/`, и положи туда
> скопированные `memory\` и `*.jsonl`.

## 6. Полезные заметки
- **Docker после перезагрузки ноута сам не стартует** → запускать Docker Desktop вручную, потом `docker compose start`.
- **Порт 3000 занят** (частая ситуация: авто-форвард VS Code) → закрой форвард в панели *Ports* VS Code, либо поменяй в `docker-compose.yml` левую часть `127.0.0.1:3000:3000` на `3001:3000`.
- **Обновить данные** позже: заменить `backup/livs_bi.dump` свежим дампом и повторить шаг 3.3, либо грузить новые отчёты через GUI (:8501).
- **Свежий дамп сделать так** (на исходном ПК): `docker compose exec -T db pg_dump -U livs -d livs_bi -Fc -f /tmp/livs_bi.dump; docker cp livs_db:/tmp/livs_bi.dump backup/livs_bi.dump`.
